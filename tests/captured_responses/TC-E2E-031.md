## Summary
Instrument dbt + Airflow with OpenLineage emission to your catalog plane, define freshness/completeness SLIs, and alert on multi-window burn-rate breaches before customer-facing SLOs fail.

## Decision
Adopt OpenLineage as the canonical run-event format: emit from Airflow (`OpenLineageOperator` or facet on task completion) and dbt (`dbt-ol` / manifest + run results export). Route events to Marquez or DataHub. Define SLIs on pipeline freshness and row-count completeness; page on 1h/6h burn-rate alerts tied to `templates/slo_definition.md`.

## Rationale
Observability by default (W007) and lineage is not optional (W009). Without OpenLineage-compatible events, you cannot answer "what broke downstream?" when a mart column disappears. Burn-rate alerting catches gradual degradation before an absolute SLO miss — cheaper than incident firefighting.

## Trade-offs
| Option | Pros | Cons | When to Use |
|--------|------|------|-------------|
| OpenLineage + catalog (DataHub/OpenMetadata) | Unified run + column lineage | Initial wiring effort | Production dbt + Airflow stacks |
| Metrics-only (duration/row counts) | Fast to ship | No column-level blast radius | Early-stage pipelines |
| Manual lineage docs | Zero tooling | Stale within weeks | Not recommended at scale |
